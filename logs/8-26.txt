quadtree refactor [entity -> id]
the tree already works, this is a type change plus shedding two responsibilities
it should never have had. node objects_ becomes vector<size_t>

what leaves the quadtree entirely:
-> the per object update loop, the graveyard, to_remove
   entities dont update themselves anymore, the systems drive that and the
   lifespan system already handles removal
-> the interact() calls in perform_interactions and identify_collisions.
   polymorphic dispatch on entity type isnt possible from an id, and it isnt the
   tree's job. identify_collisions returns candidate pairs, the collision /
   interaction system resolves them
-> next_ids_ / next_id_. entity_lifespan_system already owns id allocation and
   recycling, two allocators is one too many

what stays, just needs a bounds lookup where the entity used to carry its own
geometry. one bounds_for(id) off the collision component covers all of them:
-> insert
-> is_there_collision
-> perform_interactions
-> the left-its-node check in update
-> identify_collisions

movement system status
-> path class exists. holds source, destination, the waypoint list and an optional destination entity.
   destination is kept separately on purpose, find_path returns grid snapped node positions and the
   destination is the exact requested point, they are not the same value. source is probably dead
   weight, nothing reads it
-> movement component holds a queue of paths. set_path replaces the whole queue, append_path adds a
   leg. has_reached_position is the tolerance check ported off dog::reached_position, minus the snap
   because the component cannot write position
-> create_path is private, takes source/direction/destination and returns optional<path>. nullopt
   when find_path comes back empty, so unreachable has no valid representation and the caller cannot
   forget to check
-> create_path_to event is a placeholder command, carries id, destination, assignment mode and the
   optional destination entity. handler resolves the source by mode, current position for replace,
   the last queued leg's destination for append, then routes properly from there instead of the old
   trick of overwriting the queued leg's first waypoint
-> update() is the port of dog::update_path. snapshot the ids first, the move_entity execute inside
   update_position could erase a component mid iteration. snap onto the waypoint, advance, on
   completion pop the leg and re-aim at the next one, no move step on the completing frame
-> determine_direction ported off dog::determine_direction, writes the scalar on the component and
   the facing index through component_helpers::set_facing_index
